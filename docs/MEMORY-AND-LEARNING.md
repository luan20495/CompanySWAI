# Memory and organizational learning

## Project memory
Readable Markdown under `.companyswai/projects/<project>/`, written automatically and idempotently: `PLAN.md` (task checklist with state, review level, skills), `REQUIREMENTS.md`, `ARCHITECTURE.md`, `DECISIONS.md` (with `DEC-` IDs), `HANDOFFS.md`, `REVIEWS.md`, `BLOCKERS.md`, `QA.md` (requirement → test traceability table), `STATUS.md` (log plus the final status block), `RETROSPECTIVE.md`. Routing is declared in `company/MEMORY.md`. Memory is a *summary*: one block per task per file (revisions replace earlier drafts), meaningful sections only, long text cut with a pointer to the artifact. Machine state — artifacts, decisions, reviews, handoffs, blockers, `traceability/<project>.json` (REQ/AC/T/DEC/ART IDs and links), `research/` (citations and the retrieved documents) — lives in structured stores; the execution log stays the resume source of truth.

## Learning loop (`company/LEARNING.md`)
1. **Retrospective** (every pass; the company learns only when the project completes): project-local lessons (fed back only to the same project) and generic *candidates* with evidence, kind (`process` or `operational`) and scope.
2. **Validation**: rejected if operational/temporary provider behaviour (rate limits, quotas, outages, prices), if it argues for weakening review/gates/approval, if it looks project-specific (project id, URL, e-mail, path, figures, credential, unknown role/skill), or if over-long. Otherwise it needs ≥ 2 distinct projects and a confidence ≥ `minConfidence` (grows with independent projects, evidence and repeat observations).
3. **Governance**: candidates touching protected topics (security, secrets, approvals, governance, gates, independence…) wait as `PENDING_APPROVAL`; a person decides with `npm run experience -- approve|reject <n>` and that decision is never overturned by later observations.
4. **Reuse**: validated lessons are injected into later plans by scope — `GLOBAL` everywhere, `ROLE:<agent>`, `SKILL:<skill>` (agents running that skill), `DOMAIN:<tag>` (projects with that signal). Dry runs and unfinished projects never teach the company. Learning only adds advisory prompt text; it never edits Markdown rules, gates, budgets or policy.
