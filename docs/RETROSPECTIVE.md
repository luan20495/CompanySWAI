# Retrospective protocol

`RETROSPECTIVE.md` in each project is generated at the end of every run: outcome, estimate-vs-actual cost by project/department/agent/task, project-local lessons, and the candidates proposed for company experience.

Humans reviewing it should ask:
1. Which coordination, decomposition or review pattern measurably helped?
2. What caused rework, waiting or unnecessary token/tool cost?
3. Is the cause project-specific (keep it local) or organizational (a candidate)?
4. When should a lesson NOT apply?

Promotion rules live in `docs/MEMORY-AND-LEARNING.md` and are enforced by `src/company-experience.ts`.
