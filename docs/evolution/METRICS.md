# Metric catalog v1

Source of truth: `src/metric-catalog.ts` (a test keeps this file in sync). Reported by `npm run scorecard`.

Rules for every metric:
- **No invented numbers.** A metric whose data does not exist is `UNKNOWN` (no data in the window) or `NOT_AVAILABLE` (not measurable until a later phase) — never 0.
- **Numerator, denominator and coverage are always shown**, so a ratio can be checked and its blind spots are visible.
- **Token sources are separate:** provider-reported, fixture-estimated (dry-run) and unknown (no usage reported) are never added together. Subscription usage has no per-call price: money is UNKNOWN, not 0.
- **Historical values are observations, not controlled experiments.** Comparing versions requires equal tasks, acceptance criteria and budgets (Phase 0 fixture, later benchmarks).
- **Recorded vs derived:** values written by Phase 0+ code are `recorded`; values reconstructed for older runs (plan source from hashes) are `derived` and labelled.

|---|---|---|---|---|---|---|---|
| `accepted_run_rate` | Accepted runs | ratio | Share of finished runs whose final status is ACCEPTED or ACCEPTED_WITH_RISKS. | runs with final status ACCEPTED or ACCEPTED_WITH_RISKS | runs with a recorded final status | runs/<project>.json final.status | A run's ACCEPTED is the engine's own verdict; before Phase 1 it can disagree with QA (see qa_conflict_rate). |
| `qa_conflict_rate` | Accepted despite QA FAIL/BLOCKED | ratio | Runs reported ACCEPTED/ACCEPTED_WITH_RISKS although at least one QA task in the run reported FAIL or BLOCKED. | accepted runs with a QA task verdict FAIL or BLOCKED | runs with at least one QA task verdict FAIL or BLOCKED | QA task output parsed with the engine's parseQa (## QA Status), runs final.status | Detection only; Phase 0 does not change the verdict. QA verdicts are the QA agent's own claims. |
| `first_attempt_gate_pass` | First attempt passes | ratio | Maker tasks whose first execution attempt succeeded (contract, validators and gates passed). | maker tasks whose earliest attempt ended SUCCEEDED | maker tasks with at least one finished attempt | executions/<project>/records.jsonl (one attempt = one record id) | Not acceptance: a successful attempt can still get CHANGES_REQUIRED from review. |
| `first_pass_acceptance` | Accepted on first pass | ratio | Tasks that became DONE with exactly one maker version and no CHANGES_REQUIRED review. | DONE tasks with one successful maker version, one maker attempt and no CHANGES_REQUIRED | tasks that are DONE or whose latest maker attempt FAILED | engine taskHistory over the execution log, plan and QA rework requests; reviews/ | Needs the persisted plan; projects without one are excluded (coverage shown). |
| `attempt_failure_rate` | Failed maker attempts | ratio | Share of finished maker attempts that failed (gate, contract, provider error or timeout). | maker attempts ending FAILED | maker attempts ending SUCCEEDED or FAILED | executions records | Mixes causes; failure signatures arrive in Phase 5. |
| `rework_token_share` | Tokens spent on failed attempts | ratio | Provider-reported tokens consumed by attempts that failed, over all provider-reported tokens. | reported input+output tokens of FAILED attempts | reported input+output tokens of all attempts | executions records (inputTokens, outputTokens, tokenSource) | Attempts without reported usage (timeouts, fixtures) are excluded; coverage shown. |
| `review_changes_required_rate` | Review asked for changes | ratio | Share of stored review verdicts that were CHANGES_REQUIRED. | review records with verdict CHANGES_REQUIRED | review records | reviews/<project>/*.json | Counts verdicts, not distinct findings. |
| `reviewer_escape_rate` | QA FAIL after review PASS (same run) | ratio | QA tasks reporting FAIL whose upstream reviewed tasks in the same run all had a final PASS review. | QA FAIL tasks with every reviewed upstream task passing review | QA FAIL tasks with at least one reviewed upstream task in the same run | plan dependencies, reviews/, QA output | Only within one run; QA run as a separate project has no recorded link to the work it checked (until Phase 3). |
| `planner_bypass_rate` | Plans supplied from outside | ratio | Runs whose plan was supplied whole instead of compiled from a brief by the company planner. | runs with plan source supplied-plan | runs whose plan source is known | runs provenance (recorded from Phase 0); older runs derived from briefHash==planHash | Derived values are labelled; a reprioritised or replanned run can make the derivation wrong. |
| `lesson_injection_rate` | Plans carrying company lessons | ratio | Runs whose persisted plan has at least one system prompt with the lessons block. | runs whose plan contains the lessons header | runs with a readable plan | runs/<project>.plan.json | Presence only; whether a lesson helped is not measured until Phase 5. |
| `reported_tokens` | Provider-reported tokens | tokens | Sum of input+output tokens the provider reported, cache tokens shown separately where reported. | reported input+output tokens | — | executions records | Subscription usage has no price; fixture (dry-run) estimates are counted separately and never added. |
| `tokens_per_accepted_run` | Reported tokens per accepted run | tokens | Reported tokens of all attempts in accepted runs, divided by the accepted runs that have any reported usage. | reported tokens in accepted runs | accepted runs with reported usage | executions records, runs | Task size differs between runs; not comparable across different work. |
| `median_attempt_ms` | Median attempt wall time | ms | Median of finishedAt - startedAt over finished attempts. | — | finished attempts | executions records timestamps | Includes provider latency and gates; not queue time. |
| `accepted_runs_per_busy_hour` | Accepted runs per busy hour | per-hour | Accepted runs divided by the hours during which at least one run had an attempt in progress. | accepted runs | hours covered by the union of run activity intervals | executions records timestamps | Runs differ in size; idle time between dispatches is excluded on purpose (see dispatch gap). |
| `dispatch_gap_ms` | Total idle gap between runs | ms | Sum of the gaps in which no run had an attempt in progress, between the first and last activity of the window. | gap time | — | executions records timestamps | Idle can be intentional (owner away); not all of it is waste. |
| `interventions_per_accepted_run` | Human interventions per accepted run | per-run | Recorded interventions linked to runs started after the intervention log existed, per accepted run among those runs. | interventions on covered runs | accepted covered runs | interventions.jsonl (Phase 0+) | Actors are self-declared; manual actions outside the engine count only if someone records them. |
| `known_cost` | Known money cost | count | Sum of actualCost on metered attempts. | actualCost | — | executions records | Subscription runs have no per-call price: their cost is UNKNOWN, never 0. |
| `skill_outcome_effect` | Skill effect on outcomes | ratio | Difference in first-pass acceptance between comparable tasks with and without a skill. | — | — | skillTrace + outcomes | **NOT AVAILABLE** — no controlled comparison exists; Phase 4. Selection is recorded, outcomes per skill are not. |
| `repeated_error_rate` | Repeated failure signatures | ratio | Failures whose normalised signature already occurred before. | — | — | failure registry | **NOT AVAILABLE** — no failure registry; Phase 5. No failure signatures are recorded yet. |
| `model_escalation_success` | Model escalation success | ratio | Escalated attempts that succeeded. | — | — | routing policy events | **NOT AVAILABLE** — no escalation policy; Phase 6. There is no escalation policy; manual model changes are only visible if recorded as interventions. |
| `release_readiness` | Release readiness | count | Features accepted and release-ready. | — | — | release states | **NOT AVAILABLE** — not tracked; Phase 7. The engine has no feature or release state. |
